# Validation and current limits

This is an experimental patch for one exact Eden v0.2.1 Windows x64 executable. Binary hashes are listed in the main README. A newly compiled C++ build was not produced in the original test environment.

## Physical-device evidence

The tested configuration used original Nintendo Joy-Con over Bluetooth, with a single left controller as player 1 and single right controller as player 2.

- Four rumble routing cases passed, including rejecting requests for the absent side.
- Six real HD packets retained independent low/high amplitudes and frequencies.
- A deliberately stalled consumer sent the newest queued sample first on resuming.
- A direct hardware diagnostic received 124 complete 40×30 IR images in 12 seconds.
- After installing the combined patch, three successive in-game IR activations returned success. Real IR fragments and more than 14,000 MomentProcessor samples reached the player-2 camera processor.
- The owner reported that the camera appeared to work in 1-2-Switch. Repeatable mouth calibration and broader gameplay acceptance need more independent testing. A working camera transport does not prove every recognition algorithm or every IR game works.

These observations are test results, not an automated guarantee for every Bluetooth adapter or controller model. Exact original-Switch tactile fidelity was not established.

The physical checks above used the prerelease with SHA256 `e1d4bcb62ca9359853f4f0a9621edc5e0d98a3e62cf940dd5abb440dcf23bf30`. The published revision additionally fixes the zero-report queue path and C++ scope metadata identified in review. Its native tests pass. A final physical rerun was inconclusive because both Joy-Con were disconnected; it is not counted as a passing device test.

## Native-code checks

The test harness executes the generated x64 routing, reply-filter and retry fragments on synthetic objects:

- 81 camera routing cases, with 72 original misrouting cases reproduced as negative controls.
- 8 reply matching cases, with 4 original false acceptances reproduced.
- 5 retry cases covering immediate success, one/two failures, and the bounded failure case.
- PE checksum, section/table layout, relative branch targets and chained unwind records.
- The invalid zero-report input path returns through queue pruning, matching the C++ source.
- The retry fragment's C++ IP-to-state map preserves the original configuration scope for its new call sites.

An independent review compared Windows `RtlVirtualUnwind` results at 36 positions across the 12 added chained code fragments with their original parent frames. This verifies stack reconstruction for those contexts; it is not a claim that every possible C++ exception was injected and tested.

Run the native verifier on Windows x64 using your own executable and the manifest generated by the patcher:

```powershell
python -m pip install -r requirements-dev.txt
python tests/verify_native.py --source "C:\Emulators\Eden\eden.original.exe" --candidate "C:\Emulators\Eden\eden.fixed.exe" --manifest "local-results\manifest.json" --report "local-results\native-check.json"
```

No emulator/game binary is supplied with the test suite. Raw controller identifiers, camera frames, game paths and private logs are excluded from the public package.

## Scope across games

The source changes act below the game layer, so other games can benefit from the corrected rumble routing and camera selection. Only the stated setup and game have physical evidence here. Tera/hand-analysis and other IRS processors may have unfinished implementations in Eden itself; this patch does not complete those algorithms.

Please distinguish in reports: camera enable/frames, recognition/calibration, game interaction, and tactile rumble behavior. Include version/hash and controller layout so reports can be reproduced.
